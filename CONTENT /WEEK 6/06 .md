## Week 6 — Linux Utilities and Shell Scripting
> 💡 **One-line summary:** This week covers productivity utilities (`find`, `tar`, `make`) and the distinct execution environments (Login/Non-login, Sourced/Executed) required for robust shell automation.

---

### 🔑 Core Concepts

#### Software Tools Principles
Software should be designed to do one thing well, process lines of text (not binary), use regular expressions for pattern matching, and default to standard I/O. This philosophy underpins the design of most Unix/Linux command-line utilities.

> 📝 **Exam note:** These four principles are a frequent MCQ topic — remember the emphasis on *text streams* and *standard I/O* as defaults.

---

#### Archiving vs. Compression
**Archiving** bundles multiple files into a single file (e.g., `tar`), while **compression** reduces file size by encoding data more efficiently. These are two distinct operations — `tar` archives but does *not* compress by default.

> 📝 **Exam note:** `tar` alone does not reduce file size. Compression requires piping through `gzip`, `bzip2`, or using combined flags like `-z` or `-j`.

---

#### Lossless vs. Lossy Compression
**Lossless compression** allows data to be perfectly reconstructed from the compressed form (e.g., `gzip`, `bzip2`, `zip`). **Lossy compression** sacrifices some data for higher compression ratios and is typically used for images and video.

---

#### Interpreter
An **interpreter** is a program that executes scripts line-by-line (e.g., Shell, AWK, sed, Python, Ruby, Perl). Interpreters allow for easier debugging because they encounter and stop at errors line-by-line. However, they are slower for repeated execution because they must re-convert to machine code every time, unlike compiled languages which reuse precompiled machine code.

> 📝 **Exam note:** Know the trade-off — interpreters are *easier to debug* but *slower to execute repeatedly* compared to compiled programs.

---

#### Shabang (`#!`)
The **shabang** (also called shebang) is the first line of a script, indicating which interpreter should execute the file. The syntax is `#!/path/to/interpreter` (e.g., `#!/bin/bash`).

---

#### Sourced Script
A **sourced script** is executed in the **current shell** (same PID). Environment changes such as variables, aliases, and functions persist after the script ends. Invoked with `source script.sh` or `. script.sh`.

---

#### Executed Script
An **executed script** runs in a **new subshell** (child process). It requires execution permissions (`chmod +x`), and its environment changes are lost upon completion because the subshell terminates.

---

#### $PATH Variable
The `$PATH` variable is a colon-separated list of directory paths the shell searches, in order, to find executable commands. If multiple directories contain a command of the same name, the shell executes the one found in the **first directory listed** in `$PATH`.

> 📝 **Exam note:** Order matters — the *first match wins*. If you want a custom script to override a system command, its directory must appear earlier in `$PATH`.

---

#### Login vs. Non-login Shell
A **login shell** (e.g., SSH session) requires credentials and sources the following files in order: `/etc/profile`, `~/.bash_profile`, `~/.bash_login`, and `~/.profile`. A **non-login shell** (e.g., opening a new terminal window) sources `/etc/bash.bashrc` and `~/.bashrc`.

> 📝 **Exam note:** Know the exact file paths for each shell type — this is a common exam question.

---

#### Shell Initialization Files
- **Login Shell:** `/etc/profile` → `~/.bash_profile` → `~/.bash_login` → `~/.profile`
- **Non-login Shell:** `/etc/bash.bashrc` → `~/.bashrc`

---

#### Command Substitution
Using `var=$(command)` or `` var=`command` `` to execute a command and store its output in a variable. The `$(...)` syntax is preferred as it supports nesting.

---

#### Exit Status
Commands return an exit status — `0` for success ("True") and non-zero for failure ("False"). This value is stored in the special parameter `$?` and is used to satisfy conditions in `if` statements.

---

#### Special Parameter `$$`
The `$$` special parameter returns the **Process ID (PID)** of the current shell. This is useful for creating uniquely named temporary files (e.g., `bundle.$$.tgz`).

> 📝 **Exam note:** `$$` gives the PID of the *current* shell, not the parent or child process.

---

#### Internal Field Separator (`IFS`)
The `IFS` variable defines how the shell splits strings into words. The default value is space, tab, and newline. It can be overridden for custom parsing (e.g., `IFS=":"` to parse `/etc/passwd` fields).

---

#### Brace Expansion
Brace expansion generates sequences: `{1..5}` produces `1 2 3 4 5`. A step value can be specified: `{1..10..2}` produces `1 3 5 7 9`.

> 📝 **Exam note:** The step syntax `{start..end..step}` is easy to overlook — remember all three dots-separated values.

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `find` | `find [path] [conditions]` | Locates files by name, type, size, or time across a hierarchy |
| `find -type d` | `find [path] -type d` | Filters results to directories only |
| `find -type f` | `find [path] -type f` | Filters results to regular files only |
| `find -type c` | `find [path] -type c` | Finds character device files |
| `find -type l` | `find [path] -type l` | Finds symbolic links |
| `find -atime` | `find [path] -atime +n` | Finds files accessed more than *n* days ago (`-n` for less than *n*) |
| `find -ctime` | `find [path] -ctime +n` | Finds files with status changed more than *n* days ago |
| `find -regex` | `find [path] -regex "pattern"` | Matches filenames using a regular expression |
| `find -exec` | `find [path] [cond] -exec cmd {} \;` | Runs a command on every file found; `{}` is the placeholder |
| `tar -cvf` | `tar -cvf archive.tar dir/` | **C**reates a **v**erbose archive **f**ile from a directory |
| `tar -xvf` | `tar -xvf archive.tar` | **E**xtracts files from a tar archive |
| `tar -tvf` | `tar -tvf archive.tar` | **T**ests/Lists the contents of a tar file without extracting |
| `gzip` | `gzip file` | Compresses a file (produces `.gz`); faster than `bzip2` |
| `gunzip` | `gunzip file.gz` | Decompresses a `.gz` file |
| `bzip2` | `bzip2 file` | Compresses with higher ratio than `gzip` (produces `.bz2`); slower |
| `bzip2 -d` | `bzip2 -d file.bz2` | Decompresses a `.bz2` file |
| `compress` | `compress file` | Older Unix compression utility (produces `.Z`) |
| `7z` | `7z a archive.7z files` | High-ratio compression utility (*requires `p7zip-full`*) |
| `xz` | `xz file` | High-ratio compression utility (*requires `xz-utils`*) |
| `make` | `make -f [file]` | Performs conditional actions based on a dependency/Makefile |
| `.PHONY` | `.PHONY : [target]` | Declares a Makefile target that is not a physical file (e.g., `clean`) |
| `read` | `read var` | Reads a string from standard input and stores it in `$var` |
| `source` | `source [file]` or `. [file]` | Executes a script in the current shell environment |
| `test` | `test [expr]` or `[ expr ]` | Evaluates a condition; requires spaces inside square brackets |
| `[[ ]]` | `[[ expr ]]` | Advanced test allowing regular expressions and complex logic |
| `(( ))` | `(( expr ))` | Performs C-style arithmetic operations and comparisons |
| `expr` | `expr $I + 1` | Evaluates and prints an expression; used for integer arithmetic in older scripts |
| `echo` | `echo [-n] "text"` | Prints text; `-n` omits the trailing newline |
| `printf` | `printf "format" args` | C-style formatted output; requires manual `\n` for newlines |
| `$$` | `echo $$` | Returns the Process ID (PID) of the current shell |

**Key flags reference — `find`:**

| Flag | Effect |
|---|---|
| `-name` | Match by filename pattern |
| `-type` | Filter by type: `f` (file), `d` (dir), `c` (char device), `l` (symlink) |
| `-size` | Filter by size (e.g., `+5M` for files larger than 5 MB) |
| `-atime` | Filter by access time (`+n` = more than *n* days, `-n` = less than *n* days) |
| `-ctime` | Filter by status change time |
| `-regex` | Match using a regular expression |
| `-regextype` | Specify regex dialect |
| `-print` | Print matching filenames (default action) |
| `-exec` | Execute a command on each match |

**Key flags reference — `tar`:**

| Flag | Effect |
|---|---|
| `-c` | Create a new archive |
| `-x` | Extract files from an archive |
| `-t` | List contents of an archive |
| `-v` | Verbose output |
| `-f` | Specify the archive filename |

**Key flags reference — `test` / `[ ]`:**

| Flag | Effect |
|---|---|
| `-e` | File exists |
| `-f` | Is a regular file |
| `-d` | Is a directory |
| `-r` | Is readable |
| `-w` | Is writable |
| `-x` | Is executable |
| `-s` | File is not empty |
| `-O` | File is owned by the current user |
| `-G` | File's group matches the current user's group |
| `-nt` | File is newer than another file |
| `-ot` | File is older than another file |

**Numeric comparison operators:**

| Operator | Meaning |
|---|---|
| `-eq` | Equal |
| `-ne` | Not equal |
| `-gt` | Greater than |
| `-lt` | Less than |
| `-ge` | Greater than or equal |
| `-le` | Less than or equal |

**String comparison operators:**

| Operator | Meaning |
|---|---|
| `=` | Strings are equal |
| `!=` | Strings are not equal |
| `<` | String sorts before (lexicographic) |
| `>` | String sorts after (lexicographic) |
| `-z` | String has zero length |
| `-n` | String has non-zero length |

**`make` variable syntax:**

| Syntax | Meaning |
|---|---|
| `VAR = value` | Assign a value to a Makefile variable |
| `$(VAR)` | Reference/access the variable in a recipe |
| `.PHONY : target` | Declare `target` as non-file to ensure it always runs |

### ⚖️ Key Comparisons & Distinctions

| `tar` | `zip` |
|---|---|
| Archives (bundles) only by default | Archives **and** compresses simultaneously |
| Requires separate compression step (`gzip`, `bzip2`) | Single-step operation |

| `bzip2` | `gzip` |
|---|---|
| Better compression ratio | Faster compression speed |
| Slower processing time | Larger output file size |
| Produces `.bz2` files | Produces `.gz` files |

| `$*` (quoted) | `$@` (quoted) |
|---|---|
| Treats all arguments as **one single string** | Treats each argument as a **separate quoted string** |
| Single iteration in a loop | Multiple iterations in a loop |

| `while` loop | `until` loop |
|---|---|
| Executes while condition is **True** (exit status 0) | Executes while condition is **False** (non-zero exit status) |

| `echo` | `printf` |
|---|---|
| Simple output; adds a newline by default | C-style format specifiers (`%s`, `%d`); no automatic newline |

| Sourced script | Executed script |
|---|---|
| Runs in the **current shell** (same PID) | Runs in a **new subshell** (child process) |
| Environment changes **persist** | Environment changes are **lost** |
| No execution permission needed | Requires `chmod +x` |

| Login shell | Non-login shell |
|---|---|
| Requires credentials (e.g., SSH) | No credentials needed (e.g., new terminal) |
| Sources `/etc/profile`, `~/.bash_profile`, `~/.bash_login`, `~/.profile` | Sources `/etc/bash.bashrc`, `~/.bashrc` |

| Interpreter | Compiled language |
|---|---|
| Executes line-by-line | Converts entire source to machine code first |
| Easier debugging (stops at error line) | Harder to pinpoint errors |
| Slower for repeated execution | Faster — reuses precompiled machine code |

### ⚠️ Common Exam Traps

- **Variable Expansion with `${11}`:** `${11}` must use braces to access the 11th positional parameter; without braces, `$11` is interpreted as `$1` followed by the literal character `1`.

- **Script Permissions:** Executing with `./script.sh` requires `chmod +x`, but `source script.sh` does not need execution permissions.

- **Case Sensitivity:** Shell variables are case-sensitive. The `case` block must be terminated with `esac` (the reverse of `case`).

- **Numeric vs. String Operators:** Use `-eq`, `-gt`, `-lt` for numeric comparisons and `=`, `!=`, `<`, `>` for string comparisons. Using the wrong operator type leads to silent logic errors.

- **File Testing — `-e` vs. `-f`:** `-e` checks if a file exists (any type), but `-f` specifically checks if it is a **regular file** (not a directory or device).

- **`$0` Path Variation:** `$0` displays exactly how the script was invoked. If called via a relative path (`./s1.sh`), it shows `./s1.sh`. If called via an absolute path, it shows the full path.

- **`printf` Newlines:** Unlike `echo`, `printf` does **not** automatically append `\n`. You must include `\n` manually in the format string.

- **`make` Variables:** In a Makefile, variables are assigned with `=` (e.g., `VAR = val`) and accessed using `$(VAR)` — do not confuse with shell variable syntax `$VAR`.

- **Tarballs with PIDs:** Unique tarball names can be created using `$$` (e.g., `bundle.$$.tgz`) to avoid filename collisions in automated scripts.

## 🏆 Master Concept List — Top 25 Exam-Critical Terms

1. **`#!` (Shabang)** — Essential header defining the script's interpreter path
2. **`source` / `.`** — Runs scripts in the current shell to preserve environment changes
3. **Child Shell (Subshell)** — A separate process created when a script is executed, preventing environment leakage
4. **`$PATH`** — Colon-separated environment variable determining command search priority; first match wins
5. **Command Substitution `$(…)`** — Syntax for capturing command output into a variable
6. **`tar` (Tape Archive)** — The standard utility for bundling file hierarchies into a single file
7. **Lossless Compression** — Compression where original data can be perfectly reconstructed; vital for backups
8. **`find -exec`** — Most powerful way to perform bulk actions on files matching specific criteria
9. **Positional Parameters (`$1`, `$2`, …)** — How scripts handle command-line arguments
10. **`$#`** — Variable representing the total count of arguments passed to a script
11. **`$?`** — The exit status of the last executed command (0 = success, non-zero = failure)
12. **`$$`** — Special parameter returning the Process ID (PID) of the current shell
13. **`read` Command** — The primary method for interactive user input in shell scripts
14. **`test` / `[ ]`** — The foundation for all conditional logic in shell scripts
15. **`-eq`, `-ne`, `-gt`, `-lt`** — Required operators for numeric comparisons inside `test`
16. **`fi` and `esac`** — Required closing keywords for `if` and `case` blocks respectively
17. **`for var in list`** — Standard loop for iterating over a set of items or command outputs
18. **`while` Loop** — Executes as long as a condition returns success (exit status 0)
19. **Function Definition** — `myfunc() { ... }` syntax for modular, reusable code blocks
20. **`$0`** — Special parameter containing the name/path used to invoke the script
21. **`chmod`** — Command needed to grant execution rights to a script file
22. **`make`** — Utility for automating tasks based on file modification times and dependencies
23. **`printf`** — Preferred command for formatted output; does not append trailing newline
24. **Login Shell** — Shell environment that loads global and user profile settings on credential-based access
25. **`IFS` (Internal Field Separator)** — Variable defining how the shell splits strings; default is space/tab/newline
