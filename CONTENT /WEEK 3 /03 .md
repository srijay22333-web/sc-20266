## Week 3 — Streams, Redirections, and System Management
> 💡 **One-line summary:** Week 3 covers the essential mechanics of managing data flow through streams, redirections, and pipes, alongside the administrative tasks of managing software packages and system processes.

---

### 🔑 Core Concepts

#### File Descriptors (FD)
Process-unique integer identifiers assigned by the OS to identify open files or resources. Every process is born with three default file descriptors: `0` (stdin), `1` (stdout), and `2` (stderr). The mapping of these descriptors can be inspected at `/proc/PID/fd`.

> 📝 **Exam note:** File descriptors are **per-process** — two different processes can have FD 3 pointing to completely different files.

---

#### Standard Streams
- `stdin` (Standard Input, FD `0`): Defaults to the keyboard.
- `stdout` (Standard Output, FD `1`): Defaults to the terminal display.
- `stderr` (Standard Error, FD `2`): Also defaults to the terminal display, but is a separate stream from `stdout`.

> 📝 **Exam note:** Both `stdout` and `stderr` appear on the terminal by default, which makes them look identical — but they are independent streams that can be redirected separately.

---

#### Kernel Tables
Linux maintains three interconnected tables for managing data flow:

- **File Descriptor Table** — Per-process; maps FD integers to entries in the File Table.
- **File Table (System File Table)** — System-wide; records the open mode (read/write), current offset, and a pointer to the Inode Table.
- **Inode Table** — Links to the actual data blocks on disk.

The `isatty()` function can be used programmatically to detect whether an FD is connected to a terminal or has been redirected to a file.

> 📝 **Exam note:** This is why `ls` changes its output format when redirected — it uses `isatty()` to detect whether stdout is a terminal.

---

#### Redirection
The process of the shell mapping a standard stream to a file or resource **before** a command executes. The shell sets up all redirections first, then runs the command.

---

#### Here Document (`<<EOF`)
Redirects a multi-line block of text into a command's `stdin` using a user-defined delimiter (commonly `EOF`). Supports variable expansion unless the delimiter is quoted (`<<'EOF'`).

> 📝 **Exam note:** Quoting the delimiter (`<<'EOF'`) disables variable expansion inside the block — an easy MCQ trap.

---

#### Here String (`<<<`)
Syntactic sugar to feed a single-line string directly into a command's `stdin` without needing `echo` and a pipe.

---

#### Pipe (`|`)
An operator that connects the `stdout` of one process directly to the `stdin` of another, following the Unix philosophy of chaining modular tools. Each side of the pipe runs in its own subshell.

---

#### Named Pipe (`mkfifo`)
A special file created with `mkfifo` that acts as a memory buffer for inter-process communication. Unlike regular files, it does **not** store data on disk. The writer blocks until a reader is present, and vice versa.

> 📝 **Exam note:** The shell is "named-pipe-aware" — redirection with `>` will **not** truncate a FIFO, unlike a regular file.

---

#### Package Management
Systems that handle installation, updating, removal, and dependency management of software. Two major families exist:
- **DEB** — Used by Debian/Ubuntu (tools: `apt`, `dpkg`).
- **RPM** — Used by Red Hat/Fedora (tools: `yum`, `dnf`, `rpm`).

Additional management tools include **Synaptic** (GUI-based) and **Aptitude** (advanced CLI-based).

Package sources are configured in `/etc/apt/sources.list` (for Ubuntu defaults) and `/etc/apt/sources.list.d/` (for third-party repositories).

---

#### Package Priorities
Packages are classified by priority to indicate their importance to the system:
- *Required:* Essential for system functioning.
- *Important:* Necessary for a well-running system.
- *Standard:* Included in a default installation.
- *Optional:* Can be omitted to save space.
- *Extra:* Specialized requirements; may conflict with higher-priority packages.

---

#### Checksums
Algorithms used to produce unique strings to verify the authenticity and integrity of downloaded files:
- **MD5** — 128-bit hash
- **SHA1** — 160-bit hash
- **SHA256** — 256-bit hash

> 📝 **Exam note:** Know the bit lengths — MD5 (128), SHA1 (160), SHA256 (256). SHA256 is the most secure of the three.

---

#### Sudo (Superuser Do)
A command used to execute administrative tasks with elevated privileges. The list of authorized users is stored in `/etc/sudoers`. All `sudo` usage is logged in `/var/log/auth.log`.

---

#### Process
An instance of a running program containing its code and activity. Each process is uniquely identified by a **Process ID (PID)** and has a **Parent Process ID (PPID)**. The very first process is `init` (PID 1), which is the ancestor of all other processes.

---

#### Process Creation (`fork`)
Processes are spawned via the `fork()` system call, which creates a parent-child relationship. If a parent process dies, the child is **adopted** by `init` (PID 1) — it does not die along with its parent.

---

#### Job Control
The shell's ability to manage processes in different states:
- **Background** — Started with `&` or moved with `bg`.
- **Foreground** — Brought to the front with `fg`.
- **Suspended** — Paused with `Ctrl+Z`.

---

#### Exit Codes (`$?`)
A number (0–255) returned by a process to its parent upon termination. `0` indicates success; non-zero values indicate specific errors.

| Exit Code | Meaning |
|---|---|
| `0` | Success |
| `1` | General error |
| `2` | Misuse of shell command |
| `126` | Command found but cannot execute (permission denied) |
| `127` | Command not found |
| `128` | Invalid argument to `exit` |
| `128+N` | Process killed by signal N (e.g., `130` = SIGINT) |
| `255` | Exit status out of range |

> 📝 **Exam note:** Exit statuses provided to `exit` are taken **modulo 256**; `exit 300` results in an exit code of `44`.

---

#### Subshell
A child shell created to execute commands independently using `(command)` syntax. The `$BASH_SUBSHELL` variable tracks the nesting level (0 = main shell, 1 = first subshell, etc.).

---

#### Shell Identity Variables
- `$-` — Returns current shell option flags (e.g., `h` for hash, `B` for brace expansion, `i` for interactive).
- `$$` — Returns the Process ID (PID) of the current active shell.
- `$?` — Returns the exit status of the most recently executed command.

### Signal Reference Table

| Number | Name | Effect | Trapable? |
|---|---|---|---|
| 1 | `SIGHUP` | Hangup; sent when terminal closes | Yes |
| 2 | `SIGINT` | Interrupt; sent by `Ctrl+C` | Yes |
| 9 | `SIGKILL` | Immediate, forced termination | **No** |
| 15 | `SIGTERM` | Software termination (graceful; default for `kill`) | Yes |
| 18 | `SIGCONT` | Resume a paused process | Yes |
| 19 | `SIGSTOP` | Immediate pause | **No** |
| 20 | `SIGTSTP` | Pause request (sent by `Ctrl+Z`); allows cleanup | Yes |

> 📝 **Exam note:** `SIGKILL` (9) and `SIGSTOP` (19) are the only two signals that **cannot** be trapped, caught, or ignored.

### ⚖️ Key Comparisons & Distinctions

| Concept A | Concept B |
|---|---|
| `>` truncates (overwrites) the target file | `>>` appends to the end of the target file |
| `apt` is a high-level manager that resolves dependencies automatically | `dpkg` is a low-level tool for manual `.deb` file manipulation only |
| `apt-get remove` uninstalls the package but keeps config files | `apt-get purge` removes the package **and** all configuration files |
| `SIGTERM` (15) asks a process to exit gracefully (default `kill` signal) | `SIGKILL` (9) forces immediate termination and **cannot** be ignored |
| `ps` provides a static, one-time snapshot of processes | `top` provides a real-time, continuously updating interactive table |
| `&` runs a process in the background | `coproc` runs it in the background **with** a two-way pipe for shell interaction |
| `man` displays documentation for external binary commands | `help` displays documentation for shell builtins |
| `nohup` makes a process immune to `SIGHUP` (terminal close) | `disown` removes a process from the shell's job table |
| `setsid -f` creates a new session (PPID becomes 1) | `nohup` keeps the same session but ignores `SIGHUP` |
| Here Document (`<<`) feeds multi-line text into `stdin` | Here String (`<<<`) feeds a single-line string into `stdin` |
| Regular pipe (`\|`) is anonymous and exists only during execution | Named pipe (`mkfifo`) persists in the filesystem until deleted |

### ⚠️ Common Exam Traps

- **Redirection Order Matters:** `command 2>&1 > file` is a **trap** — it redirects `stderr` to the current `stdout` (terminal) and *then* moves `stdout` to the file. The correct order to capture both is `command > file 2>&1`.

- **Truncation Before Execution:** Redirection operators (`>`) truncate the file **before** the command runs. Running `cat file > file` results in an **empty** file because the shell empties `file` before `cat` can read it.

- **`echo` and Pipes:** `echo hi | echo` does nothing because the second `echo` **ignores its standard input** — it only prints its own arguments.

- **Stdin Ignorance:** Commands like `ls`, `mkdir`, `rm`, `touch`, and `echo` **do not read from standard input**. Piping data to them (e.g., `echo "file" | rm`) will not work as expected.

- **`ls` Output Changes:** When redirected to a file, `ls` typically switches from a multi-column terminal format to a single-column format (detected via `isatty()`).

- **Exit Code Modulo:** Exit statuses provided to `exit` are taken **modulo 256**. For example, `exit 300` results in an exit code of `44` (300 - 256).

- **Exit Code from Signals:** If a process is killed by a signal, its exit code is **128 + signal number**. Example: `Ctrl+C` (SIGINT, signal 2) results in exit code `130`.

- **Standard Input Redirection Hides Filename:** Using `wc < file` causes `wc` to only print numbers, **omitting the filename** because it doesn't know the input came from a file.

- **Subshell Nesting Syntax:** You cannot nest subshells by putting parentheses side-by-side `((...))` — that is arithmetic evaluation. You must use a colon no-op: `(:; (command))`.

- **`nohup` Is Not Just Redirection:** `nohup` specifically makes the process **immune to the SIGHUP signal** — it is not merely a form of output redirection.

- **Named Pipe Truncation:** Redirection (`>`) usually truncates files, but the shell is "named-pipe-aware" and will **not** truncate a FIFO.

## 🏆 Master Concept List — Top 25 Exam-Critical Terms

1. **`|` (Pipe)** — Connects the standard output of one command to the standard input of the next
2. **`>` (Standard Output Redirection)** — Directs command output to a file, overwriting its contents
3. **`2>` (Standard Error Redirection)** — Specifically captures error messages from a command into a file
4. **`$?` (Exit Status)** — Variable containing the return code of the last executed command; `0` is success
5. **PID (Process ID)** — A unique integer assigned by the kernel to identify every running process
6. **`apt-get install`** — High-level command to download and install software with dependency resolution
7. **`sudo`** — Executes a single command with root/administrative privileges
8. **`SIGKILL` (`-9`)** — An unstoppable signal that immediately terminates a process
9. **`<` (Standard Input Redirection)** — Feeds the content of a file into a command's standard input
10. **`>>` (Append Redirection)** — Adds command output to the end of a file without overwriting
11. **`ps aux`** — Snapshot command used to view every running process on the system
12. **`jobs`** — Lists all processes currently managed by the active shell's job table
13. **`2>&1`** — Merges the error stream into the output stream
14. **`/dev/null`** — The "black hole" device used to discard unwanted output or errors
15. **`dpkg`** — The low-level backend for Debian package management
16. **`top`** — Interactive real-time system monitor for CPU and memory usage
17. **`grep`** — Tool often used in pipes to filter text based on patterns
18. **`wc -l`** — Counts the number of lines in a file or stream
19. **`tee`** — Allows viewing output on screen while simultaneously saving to a file
20. **`chmod`** — Used to change file permissions to make a script executable
21. **`$(...)` (Command Substitution)** — Mechanism to use the output of one command as an argument for another
22. **`lsb_release -a`** — Displays distribution-specific information like Ubuntu version
23. **`uname -a`** — Prints system information including the kernel version and architecture
24. **`md5sum` / `sha256sum`** — Tools used to generate checksums for file verification
25. **`fg` / `bg`** — Commands used to move jobs between the foreground and background
