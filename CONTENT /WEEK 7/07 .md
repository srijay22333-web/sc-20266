## Week 7.1 — Bash Scripts & Shell Arithmetic
> 💡 **One-line summary:** Week 7.1 introduces automated Bash scripting, emphasizing various syntax methods for performing integer arithmetic and handling multi-line input redirection.

---

### 🔑 Core Concepts

#### Bash Script
A script written in the **Bash** (Bourne Again Shell) programming language, used to automate tasks and interact with the OS. Scripts can be written directly in the CLI or saved as `.sh` files for execution.

> 📝 **Exam note:** To execute a script directly (e.g., `./script.sh`), the file must have the executable bit set — typically `755` permission or `chmod +x`.

#### Debugging (`set -x`)
A shell option that prints each command and its arguments to the terminal as they are executed. This is invaluable for tracing script behavior line by line during development.

#### Logical Operators
Used to combine conditions in shell scripts. `&&` represents logical **AND** (true if both conditions are true), while `||` represents logical **OR** (true if either condition is true).

#### Shell Arithmetic
Various constructs to evaluate **integer** expressions in Bash, including `let`, `expr`, `$[]`, and `$(( ))`. Each has slightly different syntax rules and output behavior.

#### Heredoc (`<<`)
A feature that redirects multiple lines of input into a script or command until a specified **delimiter** is found. Custom markers such as `EOF`, `ABC`, or any string can be used as delimiters.

#### Heredoc Indentation (`<<-`)
A variant of heredoc that ignores **leading tabs** in the input text, allowing the heredoc body to be indented within the script for readability.

#### Internal Field Separator (`IFS`)
A special shell variable that defines the character(s) used to split strings into fields. The default value is space/tab/newline. It can be reassigned (e.g., `IFS=:`) to parse colon-delimited data like `/etc/passwd`.

#### Regex Quantifier (`+`)
In a regular expression, `+` indicates that the preceding character or group must appear **one or more** times. For example, `[0-9]+` matches any sequence of one or more digits, commonly used for natural number validation.

#### Script Permissions
To execute a script directly (e.g., `./script.sh`), the file must have the **executable bit** set. This is typically achieved with `chmod 755 script.sh` or `chmod +x script.sh`.

#### Indentation in Bash
Unlike Python, **indentation in Bash is purely cosmetic** — it improves readability but does not affect the logical execution of the script in any way.

---

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `set -x` | `set -x` | Turns on debugging mode to print commands and arguments during execution |
| `set +x` | `set +x` | Turns off debugging mode |
| `let` | `let "var = expr"` | Evaluates an arithmetic expression and assigns it to a variable; no spaces around `=` unless quoted |
| `expr` | `expr [expr]` | Evaluates an expression and prints the result directly to standard output |
| `$(( ))` | `$(( expression ))` | Arithmetic expansion; substitutes the result of the calculation into a command or variable |
| `(( ))` | `(( expression ))` | Standalone arithmetic construct for evaluations or comparisons directly in the shell |
| `bc` | `bc -l` | Activates the "Basic Calculator" for floating-point arithmetic and high-precision math |
| `<<-` | `<<- DELIMITER` | Heredoc variant that ignores leading tabs in the input text |

**Key flags reference:**

| Flag | Effect |
|---|---|
| `-x` (set) | Enables debug mode — prints commands as they execute |
| `+x` (set) | Disables debug mode |
| `-l` (bc) | Loads the math library for floating-point support |

**`expr` string operators:**

| Operator | What it does |
|---|---|
| `match` | Matches a string against a pattern |
| `substr` | Extracts a substring from a string |
| `index` | Finds the position of a character in a string |
| `length` | Returns the length of a string |

---

### ⚖️ Key Comparisons & Distinctions

| `(( ))` | `$(( ))` |
|---|---|
| Standalone evaluation (e.g., `(( a++ ))`) | Substitutes the result (e.g., `echo $(( 2+2 ))`) |
| Used for side effects and comparisons | Used when you need the *value* of the expression |

| `expr` | `$(( ))` |
|---|---|
| Outputs results directly to the terminal | Requires `echo` to display the result |
| External command — requires spaces between tokens | Built-in — more flexible syntax |
| Special chars (`*`, `<`, `>`) must be escaped | No escaping needed |

| CLI Bash | `.sh` Script File |
|---|---|
| Commands typed directly in the terminal | Commands saved in a file for reuse |
| Suitable for quick, one-off tasks | Suitable for automation and complex workflows |

| Indentation (Bash) | Indentation (Python) |
|---|---|
| Purely cosmetic — no effect on logic | Mandatory — defines code blocks |

---

### ⚠️ Common Exam Traps
- **Escaping `expr` operators:** In `expr`, characters like `*`, `<`, `>`, `|`, and `&` must be escaped with a backslash (e.g., `expr 5 \* 2`) because they have special meanings in the shell.
- **`expr` spacing:** `expr` requires spaces between **every** token. `expr 5 + 2` is valid, but `expr 5+2` is **not**.
- **Default `bc` scale:** By default, `bc` has a `scale` of `0`. To perform division with decimal results, you must explicitly set `scale=n` or use the `-l` flag.
- **`bc` scale variable:** Inside `bc`, use `scale=n` to set the number of decimal places for calculations (e.g., `scale=5`).

## Week 7.2 — Control Structures & Process Management
> 💡 **One-line summary:** Week 7.2 covers advanced flow control including conditional branching, C-style loops, and process-level commands like `shift` and `exec`.

---

### 🔑 Core Concepts

#### `if-elif-else-fi`
A conditional structure where the shell executes specific command sets based on whether conditions are true. The block **must** end with `fi`.

> 📝 **Exam note:** Shell control structures are closed by reversing the opening keyword — `if` ends with `fi`, `case` ends with `esac`. This is the **Reverse Keyword Rule**.

#### `case-esac`
A multi-way branch that matches a variable against patterns. More efficient than nested `if` statements for fixed choices. Uses `|` for multiple patterns and `*` as a wildcard default. Each pattern block ends with `;;`.

#### C-Style `for` Loop
A loop structure using the `(( initialization; condition; increment ))` format, allowing fine control over loop variables. Multiple variables can be initialized/incremented by separating them with commas.

#### Brace Expansion
A range syntax used to generate sequences. For example, `{1..5}` expands to `1 2 3 4 5` and `{a..z}` expands to the full alphabet. Often used in `for` loops as a compact alternative to C-style syntax.

#### Loop Redirection
The ability to redirect the entire output of a loop (like `while` or `for`) into a file using `done > file`.

#### Positional Parameter Shifting
Moving arguments `$2` to `$1`, `$3` to `$2`, etc., effectively "consuming" arguments one at a time. Essential for processing variable-length argument lists.

> 📝 **Exam note:** Bash only supports direct access to positional parameters `$0`–`$9`. To access the 10th argument and beyond, you must use `shift` to move higher-index parameters into the `$1`–`$9` range.

#### Exit Status
A numeric value returned by every command and script. `0` indicates **success**, while any value from `1` to `255` indicates an **error** or abnormal termination. The exit status of the last command is stored in `$?`.

#### Process ID (`$$`)
The special variable `$$` holds the **Process ID (PID)** of the current shell. Useful for creating unique temporary filenames or logging.

---

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `if` | `if [ cond ]; then ... fi` | Starts a conditional block; must end with `fi` |
| `case` | `case $var in pattern) ... ;; esac` | Matches a variable against patterns; ends with `esac` |
| `for` (C-style) | `for (( i=0; i<10; i++ ))` | C-style loop with initialization, condition, and increment |
| `for` (brace) | `for i in {1..10}` | Loop using brace expansion for ranges |
| `break` | `break [n]` | Exits the current loop; `break 2` exits the outer loop in nested structures |
| `continue` | `continue` | Skips the rest of the current loop iteration and moves to the next one |
| `shift` | `shift [n]` | Discards `$1` (or `n` parameters) and shifts all other positional parameters to the left |
| `exec` | `exec [command]` | Replaces the current shell process with a new program; the shell does not return if successful |
| `man test` | `man test` | Displays documentation for all conditional flags (e.g., `-z`, `-n`, `-eq`, `-f`) used in `if` statements |

**Key flags reference:**

| Flag / Syntax | Effect |
|---|---|
| `break 2` | Exits 2 levels of nested loops |
| `shift n` | Shifts positional parameters left by `n` positions |
| `-e` (test) | True if file exists |
| `-f` (test) | True if file is a regular file |
| `-eq` (test) | Integer equality comparison |
| `-z` (test) | True if string is empty |
| `-n` (test) | True if string is non-empty |

---

### ⚖️ Key Comparisons & Distinctions

| `break` | `continue` |
|---|---|
| Terminates the loop **entirely** | Only skips the **current iteration** |
| Accepts `n` to break out of nested loops | Resumes at the top of the loop |

| `if` | `case` |
|---|---|
| Handles complex ranges and logic | Optimized for matching specific patterns or strings |
| Uses `then` / `elif` / `else` / `fi` | Uses `in` / `)` / `;;` / `esac` |

| `[` (single bracket) | `[[` (double bracket) |
|---|---|
| POSIX-compliant test | Bash-specific extended test |
| Does **not** support regex matching | Required for regex matching with `=~` |

| Param `$1`–`$9` | Param `$10` and beyond |
|---|---|
| Directly accessible | Must use `shift` to bring into range |

---

### ⚠️ Common Exam Traps
- **Infinite loops with `shift`:** If using `while [ -n "$1" ]`, failing to include `shift` or not quoting `"$1"` can lead to an infinite loop.
- **`exec` termination:** Any commands placed after a successful `exec` in a script will **never** run because the shell process is replaced entirely.
- **`break 2` in nested loops:** `break` without a number only exits the innermost loop. To exit an outer loop from within a nested inner loop, you must specify the nesting level (e.g., `break 2`).
- **Reverse keyword rule:** Forgetting the closing keyword (`fi`, `esac`, `done`) or misspelling it is a common syntax error. Remember: the closing keyword is the opening keyword **reversed**.
- **Exit status confusion:** `0` means **success** (not failure). Non-zero (`1`–`255`) means error. This is the opposite of many programming language conventions.

## Week 7.3 — Advanced Scripting Features
> 💡 **One-line summary:** Week 7.3 focuses on modularity through functions and `source`, and robust user-interaction techniques using `getopts` and `select`.

---

### 🔑 Core Concepts

#### `source` (or `.`)
Executes a script file within the *current* shell environment, allowing variables and functions defined in that script to **persist** after execution. Written as `source file` or `. file`.

#### `eval`
Evaluates its arguments as a single string and executes the result as a command. Useful for executing dynamically generated command strings where variable names or commands are constructed at runtime.

#### Bash Functions
Named blocks of code defined with `name() { ... }` that can be called with arguments. Inside the function, arguments are accessed as `$1`, `$2`, etc. — these are **separate** from the script's positional parameters.

#### Options vs Arguments
**Options** (flags like `-a`, `-f`) modify the behavior of a command, while **arguments** are the data (like filenames) the command operates on.

#### `getopts`
A shell **builtin** used to parse command-line options and their associated arguments. It processes flags one at a time in a loop and stores the current option in a variable.

#### `OPTIND` and `OPTARG`
`OPTIND` stores the **index** of the next parameter to be processed by `getopts`. `OPTARG` stores the **argument** value associated with an option that requires one.

#### Internal Field Separator (`IFS`)
A special variable that defines the character used to split strings into fields. Default is space/tab/newline. Can be changed to parse structured data (e.g., `IFS=:` for colon-separated values).

#### `read`
A builtin command that pauses the script to capture **user input** from the keyboard and stores it in a specified variable.

#### Regex Operator (`=~`)
The tilde-equals operator used within `[[ ]]` double brackets to perform **regular expression matching** against a variable. Returns true if the pattern matches.

---

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `man` | `man [command]` | Displays concise manual pages for Linux commands |
| `info` | `info [command]` | Provides detailed documentation for Linux commands, more extensive than `man` |
| `help` | `help [command]` | Displays detailed info specifically for Bash built-in commands |
| `eval` | `eval [args]` | Combines arguments into a string and executes it as a shell command |
| `source` | `source [file]` or `. [file]` | Reads and executes a file in the current shell environment |
| `getopts` | `getopts [optstring] [var]` | Parses positional parameters for specific flags |
| `select` | `select var in [list]` | Creates an interactive numbered menu for user selection |
| `read` | `read [var]` | Pauses the script to capture user input from the keyboard and stores it in `var` |
| `[[ =~ ]]` | `[[ $var =~ $regex ]]` | Matches a variable against a regular expression within double brackets |
| `man test` | `man test` | Displays documentation for all conditional flags used in `if` statements |
| `scale` | `scale=n` *(inside `bc`)* | Sets the number of decimal places to display for calculations |

**Key flags reference:**

| Flag / Syntax | Effect |
|---|---|
| `getopts "ab:c"` | Parses flags `-a`, `-b` (with required argument), and `-c` |
| Leading `:` in optstring | Suppresses default error messages (silent mode) |
| Colon after letter (`b:`) | That option **requires** an argument |
| `?` case in getopts | Handles invalid/unknown options |
| `:` case in getopts | Handles missing required arguments |

---

### ⚖️ Key Comparisons & Distinctions

| `getopts` (builtin) | `getopt` (external) |
|---|---|
| Bash builtin — simpler syntax | External program — more complex |
| Handles empty flags gracefully | Supports **long options** (e.g., `--verbose`) |
| Preferred for most Bash scripts | Used when long options are needed |

| `man` | `info` | `help` |
|---|---|---|
| Concise manual pages | Detailed documentation | Bash builtins only |
| For general Linux commands | For general Linux commands | Strictly for builtins |

| `source file` | `./file` |
|---|---|
| Runs in the **current** shell | Runs in a **new** child shell |
| Variables and functions **persist** | Variables and functions are **lost** after execution |

| Indentation (Bash) | Indentation (Python) |
|---|---|
| For readability only | Defines code block structure |
| No effect on execution | Affects execution logic |

---

### ⚠️ Common Exam Traps
- **`getopts` colon syntax:** In the `optstring`, a **leading** colon (`:abc`) suppresses default error messages. A colon **after** a letter (`b:`) means that option *requires* an argument. These are two entirely different uses of the colon.
- **`OPTIND` reset:** `getopts` uses `OPTIND` to track the next index. If parsing multiple times in one script, it may need manual resetting with `OPTIND=1`.
- **`select` loop is infinite:** The `select` loop runs indefinitely by default and requires an explicit `break` to exit.
- **Regex in single brackets:** Regular expression matching (`=~`) will **fail** if used within single brackets `[ ]`. Double brackets `[[ ]]` are **mandatory** for regex.
- **`source` vs `./`:** Students often confuse these. `source` keeps everything in the current shell; `./` spawns a new process. Variables set in a sourced script are available afterward; variables set in `./script.sh` are not.
- **`getopts` error handling:** The `?` case handles invalid options, while the `:` case handles missing required arguments — do not confuse the two.
