## Week 9.1 — awk Programming pt. 1 (Introduction & Execution Model)
> 💡 **One-line summary:** `awk` is a data-driven language that processes structured text through an implicit line-by-line loop, matching records against pattern-action rules.

---

### 🔑 Core Concepts

#### `awk` — The Language
`awk` is a POSIX-standard programming language designed for processing structured data organized into **fields** and **records**. It was created by **Aho, Weinberger, and Kernighan**. Common variants include `nawk` (BSD), `gawk` (GNU), and `mawk`.

> 📝 **Exam note:** `awk` uses **Extended Regular Expressions (ERE)** — the same class as `egrep` — because co-author Alfred Aho also authored `egrep`. This is a frequently tested distinction.

#### Record
A **record** is a single unit of input. By default, one record equals one line of text, separated by the newline character `\n`. The record separator is controlled by the built-in variable `RS`.

#### Field
A **field** is a subunit of a record — typically a word. By default, fields are separated by whitespace (spaces or tabs). The field separator is controlled by the built-in variable `FS` or the `-F` command-line flag.

#### Execution Model (Implicit Loop)
`awk` reads input line by line in an **implicit loop**, testing each record against patterns and executing associated code blocks (procedures) when a match occurs. There is no need to write explicit read/loop logic.

#### Pattern-Action Pair
The basic syntax is `pattern { action }`. If the pattern is omitted, the action applies to **all** records. If the action is omitted, the default action is to `print` the record (`$0`).

> 📝 **Exam note:** An empty pattern matches every line. A missing action block defaults to `{ print $0 }`.

#### Built-in Variables
Special variables maintained by `awk` that track the program's state, such as the current record number (`NR`), the number of fields (`NF`), or the filename being read (`FILENAME`).

#### Dynamic Typing (Loose Typing)
`awk` variables are not declared with types; their type (number or string) is determined by the value assigned or the operation performed on them. Use `typeof(var)` to inspect whether a variable is `"unassigned"`, `"number"`, or `"string"`.

> 📝 **Exam note:** Uninitialized variables default to `0` in numeric contexts and an empty string `""` in string contexts — they do **not** throw an error.

#### Numeric Strings
Input strings that look like numbers are called **numeric strings**. `awk` treats them as numbers in numeric operations and as strings in string operations. The comparison type depends on the other operand.

#### Extended Regular Expressions (ERE)
Unlike tools that use Basic Regular Expressions (BRE), `awk` uses **ERE** natively. Metacharacters like `+`, `?`, `|`, and `()` work directly without backslash escaping.

#### Range Patterns
The comma syntax `pattern1, pattern2 { action }` selects all records starting from the first match of `pattern1` to the first subsequent match of `pattern2`, inclusive. For example, `NR==3, NR==7` processes lines 3 through 7.

> 📝 **Exam note:** Range patterns are inclusive on both ends. Once the second pattern matches, the range closes and can reopen if the first pattern matches again later.

#### Concatenation
String concatenation in `awk` is performed by placing two values side-by-side separated by a **blank space**. There is no explicit operator like `+` for strings. For example: `print "Result: " $1`.

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `awk` | `awk -F":" '{print $1}'` | Sets the field separator to `:` and prints the first field of every record |
| `awk -f` | `awk -f script.awk [file]` | Executes an `awk` program stored in the specified file |
| `awk -v` | `awk -v var=val '{...}'` | Assigns a value to a variable from the command line *before* the script starts |
| `$0` | `{print $0}` | Refers to the entire current input record |
| `$n` | `{print $1, $3}` | Refers to the *n*th field of the current record |
| `BEGIN` | `BEGIN { commands }` | Block executed exactly once before any input files are read |
| `END` | `END { commands }` | Block executed exactly once after all input has been processed |
| `/regex/` | `/regex/ { commands }` | Executes commands for every record matching the regular expression |
| `FIELDWIDTHS` | `FIELDWIDTHS = "2 3 5"` | Splits records into fields of fixed character lengths (*gawk extension*) |

**Key flags reference:**

| Flag | Effect |
|---|---|
| `-F[char]` | Sets the input field separator at the command line |
| `-v var=val` | Sets a variable before the script starts (available in `BEGIN`) |
| `-f file` | Loads the `awk` script from an external file |

> 📝 **Exam note:** Multiple script files can be loaded using `-f lib -f script` syntax, allowing library reuse across programs.

### ⚖️ Key Comparisons & Distinctions

| `NR` | `FNR` |
|---|---|
| Tracks the **total** number of records read across **all** files | **Resets** to 1 for each new input file |
| Monotonically increasing | Resets per file |

| `FS` | `FPAT` |
|---|---|
| Defines the **separator** that splits fields | Defines a regex for what the **fields themselves** look like |
| Standard POSIX | *gawk extension* |

| `FS` | `FIELDWIDTHS` |
|---|---|
| Splits by a delimiter character/regex | Splits by **fixed character widths** |
| Standard POSIX | *gawk extension* |

| Regex Constant (`/regex/`) | String Constant (`"regex"`) |
|---|---|
| Compiled once for efficiency | Scanned twice — requires **double escaping** for special characters |
| Preferred for static patterns | Needed when the pattern is built dynamically |

| `ARGV[0]` | `ARGV[1]` |
|---|---|
| Always the program name (e.g., `gawk`) | The first user-supplied argument (usually a filename) |
| Flags like `-f` and `-v` are **excluded** from `ARGV` | Filenames and command-line assignments are included |

### ⚠️ Common Exam Traps

- **Persistent Variables:** Variables defined in per-record blocks persist into subsequent records and iterations unless manually reset. This "carry-over" can produce unexpected results.
- **Numeric Comparison Trap:** Comparing a numeric string with a number (e.g., `$1 < 10`) uses **numeric** logic, but comparing it with a string (e.g., `$1 < "10"`) uses **lexicographical** logic.
- **Uninitialized Variables:** Referencing an undefined variable does **not** throw an error; it defaults to `0` in numeric contexts and `""` in string contexts.
- **The Concatenation Trap:** `print $1 + $2` **adds** them numerically. `print $1 $2` **concatenates** them as strings. The blank-space operator is concatenation, not addition.
- **Command-Line Assignment Timing:** `awk '{print n}' n=1 file1 n=2 file2` — the variable `n` changes *between* files, not before the script starts. Use `-v` to assign before `BEGIN`.
- **Empty Regex:** Matching `//` matches the "invisible" empty string between every character (e.g., substituting on `hello` becomes `XhXeXlXlXoX`).

## Week 9.2 — awk Programming pt. 2 (Advanced Logic & Integration)
> 💡 **One-line summary:** Advanced `awk` incorporates associative arrays, complex control structures, and external shell integration to perform sophisticated text manipulation and data analysis.

---

### 🔑 Core Concepts

#### Associative Arrays
Collections of elements indexed by **strings** or numbers. They are created on the fly, use sparse storage, and behave like hash maps. There is no need to declare size or type.

> 📝 **Exam note:** Use the `index in array` syntax to check if a key exists — this checks for key existence only, **not** the value associated with that key.

#### Multidimensional Arrays
Simulated in standard `awk` via `SUBSEP` (the subscript separator, default `\034`). `gawk` supports true nested arrays as an extension. An expression like `array[i, j]` internally becomes `array[i SUBSEP j]`.

#### Control Flow
`awk` supports standard programming structures including `if-else` branches and `for`, `while`, and `do-while` loops. *gawk* additionally supports `switch-case` for multi-branching.

#### User-Defined Functions
Custom code blocks defined with the `function` keyword. Parameters are passed **by value** for scalars and **by reference** for arrays. Functions support recursion.

#### Shadowing
When a function is called, parameter names "hide" (shadow) global variables of the same name. Global variables are only accessible inside a function if they are not shadowed by a parameter.

#### Pretty Printing (`printf`)
The `printf` function allows highly controlled output formatting using format specifiers like `%d` (integer), `%s` (string), `%f` (float), etc. Unlike `print`, it does **not** append a newline automatically.

#### Coprocesses
A *gawk extension* using the `|&` operator to send data to another program and read results back, enabling two-way communication with external commands.

#### Dynamic Regex
Using a string variable on the right side of `~` or `!~` to compute a regular expression at runtime, rather than using a compiled regex constant.

#### `BEGINFILE` / `ENDFILE`
*gawk-only* hooks that execute once before and after **each** input file is opened/closed, unlike `BEGIN`/`END` which run only once for the entire program.

#### `IGNORECASE`
A *gawk* built-in variable that, when set to a non-zero value, makes all regex matches and string comparisons case-insensitive.

### ⚖️ Key Comparisons & Distinctions

| `print` | `printf` |
|---|---|
| Uses `OFS` between items and appends `ORS` (newline) automatically | Gives **exact** control over formatting; requires manual `\n` |
| Simple, quick output | Precision formatting with specifiers (`%d`, `%s`, `%f`) |

| Pass by Value (scalars) | Pass by Reference (arrays) |
|---|---|
| Changes inside a function do **not** affect the original variable | Changes inside a function **do** affect the original array |
| Applies to all scalar variables | Applies to all array arguments |

| `next` | `getline` |
|---|---|
| Returns control to the **start** of the `awk` script for the new record | Continues execution from the **current line** in the script |
| Skips all remaining rules for the current record | Reads a new line but does not restart the rule chain |

| `next` | `nextfile` |
|---|---|
| Skips the current **record** and moves to the next line | Skips the current **file** entirely and moves to the next file |

| `sub()` | `gensub()` |
|---|---|
| Modifies the target string **in place**; returns number of substitutions | Returns the modified string; leaves the original **untouched** |
| POSIX standard | *gawk extension*; more flexible (supports backreferences like `\1`) |

| `BEGIN` | `BEGINFILE` |
|---|---|
| Runs **once** at the very start of the program | Runs **once before each** new input file is opened |
| POSIX standard | *gawk extension* |

---

### ⚠️ Common Exam Traps

- **Array Membership Check:** The `index in array` syntax checks if a **key** exists. It does **not** check the value associated with that key.
- **Output Redirection Behavior:** `print > "file"` overwrites the file on the **first** call in the script, but subsequent calls to the same file **append** to it unless the file is explicitly closed with `close("file")`.
- **Heredoc for `awk`:** Large `awk` scripts can be embedded directly in bash scripts using the `<<` heredoc feature, avoiding quoting headaches.
- **The Exit-in-BEGIN Trap:** If `exit` is called in the `BEGIN` block, it skips **all** record processing and jumps straight to the `END` block (if one exists).
- **`getline` Return Values:** Always check: `1` = success, `0` = end of file, `-1` = error. Ignoring the return value can cause infinite loops or silent data loss.

## 🏆 Master Concept List — Top 25 Exam-Critical Terms

1. **Implicit Loop** — `awk`'s fundamental behavior of reading records and testing patterns automatically without explicit loop syntax
2. **`NR` (Number of Records)** — Built-in variable tracking the total number of records processed so far across all files
3. **`NF` (Number of Fields)** — Built-in variable holding the count of fields in the current record
4. **`FS` (Field Separator)** — Variable/flag defining the character(s) that split a record into fields (default: whitespace)
5. **`BEGIN` / `END`** — Special patterns for code that runs before or after all file processing
6. **Associative Array** — A collection indexed by strings, behaving like a hash map with sparse storage
7. **`$0`** — The variable representing the entire current input line (record)
8. **`$n`** — Variable for accessing specific fields (e.g., `$1`, `$2`, `$NF` for the last field)
9. **`getline`** — Command to manually read the next line of input into a variable or `$0`
10. **`printf`** — Function for formatted output using conversion specifiers (`%d`, `%s`, `%f`)
11. **`RS` (Record Separator)** — Variable defining the end-of-record marker (default: newline `\n`)
12. **`OFS` / `ORS`** — Output separators for fields and records during printing
13. **`FNR`** — Record number relative to the current file being processed (resets per file)
14. **`~` and `!~`** — Operators for matching or not matching a string against a regex
15. **`delete`** — Keyword to remove elements from an associative array
16. **`ARGC` / `ARGV`** — Variables for handling command-line arguments; `ARGV[0]` is the program name
17. **`next`** — Statement to skip remaining rules and start processing the next record
18. **`system()`** — Function to execute shell commands from within `awk` and return exit status
19. **`FPAT`** — A *gawk extension* variable to define fields by content (regex) rather than separators
20. **`FILENAME`** — Built-in variable containing the name of the file currently being read
21. **`ENVIRON`** — Associative array containing the system's environment variables
22. **`IGNORECASE`** — *gawk* variable that, when non-zero, makes regex matches case-insensitive
23. **`split()`** — Function to divide a string into an array based on a separator
24. **`sub()` / `gsub()`** — Functions for string substitution (first occurrence / global replacement)
25. **Loose Typing** — `awk`'s ability to treat variables as strings or numbers based on context
