## Week 8 — Stream Editor (sed) and Automating Scripts
> 💡 **One-line summary:** `sed` is a streamlined, one-pass text processor that prioritizes input order, uses volatile and persistent buffers for complex transformations, and integrates with system tools like `cron` for scheduled automation.

---

### 🔑 Core Concepts

#### Regex in Man Pages
Use `/regexPattern` to search within a man page. Press `n` to jump to the next match and `N` to go to the previous match. This is useful for quickly navigating large manual entries.

> 📝 **Exam note:** The keys `n`/`N` for navigating regex matches inside man pages are *different* from the `sed` commands `n`/`N`, which operate on the pattern space.

---

#### sed (Stream Editor)
A non-interactive, POSIX-compliant programming language used for processing and transforming text streams in a single pass. `sed` historically precedes `awk` and is designed for automated, scriptable text editing without user interaction.

> 📝 **Exam note:** `sed` supports Basic Regular Expressions (BRE) by default and Extended Regular Expressions (ERE) with the `-E` flag, but does **NOT** support Perl Compatible Regular Expressions (PCRE).

---

#### Input Stream
An input stream is defined as a set of lines, where each line is a sequence of characters. `sed` processes these lines one at a time in sequential order.

---

#### Execution Cycle
The sequence where `sed` processes each line through a strict three-step loop:
- **Read:** Load the next line of input into the pattern space.
- **Execute:** Apply all script commands sequentially to the contents of the pattern space.
- **Display:** Output the (possibly modified) pattern space and clear the buffer before starting the next cycle.

> 📝 **Exam note:** The pattern space is cleared at the end of *every* cycle. If you need data to persist across cycles, you must use the hold space.

---

#### Execution Order
`sed` prioritizes **Stream Order** (processing input lines from line 1 to line N) over **Script Order** (applying script commands line 1 to line N to each input line). This means each input line passes through the entire script before the next input line is read.

---

#### Pattern Space
The active, volatile data buffer where the current input line is stored for pattern matching and command execution. It is automatically cleared at the end of every cycle.

---

#### Hold Space
An auxiliary, persistent buffer used as temporary storage for data from previous lines. Unlike the pattern space, the hold space retains its contents across cycles, allowing complex multi-line operations and data movement between cycles.

---

#### Addressing
The method of selecting specific lines for processing. `sed` supports multiple addressing modes:
- **Numeric:** Single line (`5`), last line (`$`), all lines (`%`), or step/stride (`1~3` — start at line 1, process every 3rd line).
- **Zero-start step:** `0~2` selects every even-numbered line (starting from conceptual line 0).
- **Text/Regex:** Matching lines with `/regex/`.
- **Ranges:** Line-to-line (`5,15`), regex-to-regex (`/re1/,/re2/`), line-to-regex (`5,/re/`), relative (`/re/,+4`), or step matching (`/re/,~2`).

> 📝 **Exam note:** The `%` address is a shorthand for "all lines." The step syntax `first~step` is a GNU `sed` extension.

---

#### Command Grouping
Using `{ cmd; cmd; }` to group and apply multiple commands to a single address match. This avoids repeating the same address for each command.

---

#### Branching
Controlling script flow by jumping to specific labels:
- **`b label`** — Unconditional jump to `:label` (or to end of script if label is omitted).
- **`t label`** — Conditional jump, triggered **only** if the most recent `s///` substitution was successful.
- **`T label`** — Conditional jump, triggered **only** if the most recent `s///` substitution **failed**.
- **`:label`** — Defines a named label target for branching.

---

#### PCRE Support
`sed` supports Basic (BRE) and Extended (ERE) regular expressions but does **NOT** support Perl Compatible Regular Expressions (PCRE). This is a common misconception tested in exams.

---

#### Cron Tab
A system tool used to schedule and automate the execution of scripts or commands at specified times. Cron uses five time fields in strict order: **Minute** (0–59), **Hour** (0–23), **Day of Month** (1–31), **Month** (1–12), **Day of Week** (0–6, where 0 = Sunday).

- A `*` in any field acts as a wildcard meaning "every" (every minute, every hour, etc.).
- Cron jobs can be defined for specific users (e.g., `root`).
- System-level trigger directories include `/etc/rc0.d/` (shutdown), `/etc/cron.daily/`, `/etc/cron.weekly/`, etc.

> 📝 **Exam note:** The five cron fields are strictly ordered: **Minute, Hour, Day of Month, Month, Day of Week**. Confusing the order is one of the most common mistakes.

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `sed -e` | `sed -e 'script' file` | Executes the `sed` script provided directly in the command line |
| `sed -n` | `sed -n 'script' file` | Suppresses the default behavior of automatically printing the pattern space |
| `sed -f` | `sed -f script.sed file` | Reads and executes commands from a specified script file |
| `sed -i` | `sed -i 's/A/B/' file` | Enables in-place editing, modifying the original input file directly |
| `sed -i.bak` | `sed -i.bak 's/A/B/' file` | In-place edit while saving the original file with a `.bak` suffix |
| `sed -E` | `sed -E 's/(A)\|B/C/' file` | Enables Extended Regular Expressions (ERE) without backslashes for special characters |
| `sed --debug` | `sed --debug 'script' file` | Enables line-by-line debugging of script execution flow |
| `p` | `sed -n '5p' file` | Prints the current contents of the pattern space |
| `d` | `sed '1,10d' file` | Deletes the contents of the pattern space and immediately starts the next cycle |
| `s` | `s/regex/repl/flags` | Substitutes the first (or all with `g` flag) occurrence of a regex match with replacement text |
| `=` | `sed '=' file` | Prints the current input line number followed by a newline |
| `#` | `# comment text` | Comment line — ignored by `sed` during execution |
| `i` | `sed '1i Header' file` | Inserts specified text on a new line *above* the current line |
| `a` | `sed '$a Footer' file` | Appends specified text on a new line *below* the current line |
| `c` | `sed '/regex/c NewLine' file` | Changes (replaces) the entire current line with the specified text |
| `y` | `y/abc/123/` | **Transliterate:** replaces `a` with `1`, `b` with `2`, `c` with `3`. Strings must be equal length |
| `n` | `n` | Reads the next line of input into the pattern space, replacing the current line |
| `N` | `N` | Appends the next line of input to the pattern space, separated by a newline character |
| `h` / `H` | `h` or `H` | `h` copies pattern space to hold space; `H` appends it to hold space with a newline |
| `g` / `G` | `g` or `G` | `g` copies hold space to pattern space; `G` appends it to pattern space with a newline |
| `x` | `x` | Exchanges the contents of the pattern space and the hold space |
| `D` | `D` | Deletes only the *first* line of a multi-line pattern space, then restarts the cycle |
| `P` | `P` | Prints only the *first* line of a multi-line pattern space |
| `q` | `sed '10q' file` | Exits `sed` immediately without processing further lines or commands |
| `w` | `w outputfile` | Writes the current pattern space to the specified file |
| `r` | `r inputfile` | Reads a file and appends its content to the pattern space |
| `b` | `b label` | Branches unconditionally to a specified `:label` or to end of script if label is omitted |
| `t` | `t label` | Branches to `:label` only if the most recent `s///` was successful |
| `T` | `T label` | Branches to `:label` only if the most recent `s///` **failed** |
| `{ }` | `{ cmd; cmd; }` | Groups multiple commands to run on a single address match |
| `$=` | `sed -n '$=' file` | Emulates `wc -l` by printing the line number of the last line only |
| `crontab -e` | `crontab -e` | Opens the cron schedule file for the current user to edit tasks |

**Key flags reference:**

| Flag | Effect |
|---|---|
| `-n` | Suppresses default output (auto-printing of pattern space) |
| `-e` | Specifies a script string directly on the command line |
| `-f` | Reads the script from a specified file |
| `-i` | Enables in-place file editing |
| `-i.suffix` | In-place editing with automatic backup using the given suffix |
| `-E` | Enables Extended Regular Expressions (ERE) |
| `--debug` | Enables debugging output for tracking script execution |

**Substitution flags (`s///` command):**

| Flag | Effect |
|---|---|
| `g` | Replaces **all** occurrences on the line (not just the first) |
| `i` | Performs a **case-insensitive** match |
| `N` (digit) | Replaces only the **Nth** occurrence (e.g., `s/A/B/2` replaces only the second match) |

**Special substitution symbols:**

| Symbol | Meaning |
|---|---|
| `&` | Refers to the **entire matched string** in the replacement |
| `\1`...`\9` | **Backreferences** — refers to specific captured groups within parentheses |
| `\u` | Converts the **next character** to uppercase |
| `\l` | Converts the **next character** to lowercase |
| `\U` | Converts **all following characters** to uppercase |
| `\L` | Converts **all following characters** to lowercase |
| `\E` | Stops the effect of `\U` or `\L` |

**Script syntax structure:**

```
[:label] [address] command [arguments] [options] [;]
```

**Shebang for standalone scripts:**
- `#!/usr/bin/sed -f` — standard shebang for `sed` script files
- `#!/bin/sed -nf` — shebang with `-n` flag pre-applied
- Scripts require `chmod +x` or `chmod 755` to be made executable

**Addressing shorthand:**

| Address | Meaning |
|---|---|
| `5` | Line 5 only |
| `$` | Last line |
| `%` | All lines |
| `1~3` | Every 3rd line starting from line 1 |
| `0~2` | Every even-numbered line |
| `/regex/` | Lines matching the regex |
| `5,15` | Lines 5 through 15 |
| `/re1/,/re2/` | From first match of `re1` to first match of `re2` |
| `5,/re/` | From line 5 to first match of `re` |
| `/re/,+4` | From match of `re` plus the next 4 lines |
| `/re/,~2` | From match of `re` to the next even-numbered line |
| `5!` | All lines **except** line 5 |

**Multiline insert:** Use `\` at the end of a line to insert multiple lines with the `i`, `a`, or `c` commands.

**Quotes in sed:**
- **Single quotes** (`' '`) — Prevent the shell from interpreting special characters like `$` as variables. Preferred for most `sed` scripts.
- **Double quotes** (`" "`) — Allow shell variable substitution but require escaping `$` with `\$` for `sed`-specific symbols.

### ⚖️ Key Comparisons & Distinctions

| Concept A | Concept B |
|---|---|
| **Pattern Space** — volatile, cleared every cycle | **Hold Space** — persistent, retained across cycles |
| **`b`** — unconditional jump to label | **`t`** — conditional jump, only on successful substitution |
| **`t`** — branch on substitution **success** | **`T`** — branch on substitution **failure** |
| **`n`** — overwrites pattern space with next line | **`N`** — appends next line to pattern space with `\n` |
| **`-e`** — one-line commands in the terminal | **`-f`** — executes complex scripts from a file |
| **`&`** — refers to the entire matched string | **`\1`** — refers to a specific captured group within parentheses |
| **`d`** — deletes entire pattern space | **`D`** — deletes only the first line of a multi-line pattern space |
| **`p`** — prints entire pattern space | **`P`** — prints only the first line of a multi-line pattern space |
| **`y` (transliterate)** — no support for character ranges (e.g., `a-z`) | **`tr` (translate)** — supports character ranges |
| **`p` timing** — prints immediately during the cycle | **`a` timing** — appends text to a buffer that flushes only after the cycle ends |
| **Single quotes** — prevent shell variable interpretation | **Double quotes** — allow shell substitution, require `\$` escaping for `sed` |
| **Stream Order** — processing lines 1 to N sequentially | **Script Order** — applying commands 1 to N to each line |

### ⚠️ Common Exam Traps

- **Double Printing:** Using the `p` command without the `-n` flag causes matched lines to be printed twice — once by `p` and once by the default auto-print.
- **Single Substitution:** By default, `s///` only replaces the *first* match per line; the `g` flag is mandatory for global replacement across all occurrences.
- **Address Negation:** The `!` operator after an address (e.g., `5!d`) applies the command to every line *except* the one specified. This is a frequent source of confusion.
- **Cron Field Order:** The five time fields are strictly: **Minute, Hour, Day of Month, Month, Day of Week**. Getting the order wrong is the most common cron mistake.
- **N Command at EOF:** In GNU `sed`, the `N` command terminates the script immediately if there is no next line to read (end of file reached).
- **Script Permissions:** Standalone `sed` scripts must be made executable using `chmod +x` or `chmod 755` before they can be run directly.
- **Append Persistence:** The `a` (append) command prints text *after* the current line is processed, even if the command appears before a print command in the script. The appended text is buffered and flushed only at the end of the cycle.
- **Cron Asterisk:** A `*` in any cron field acts as a wildcard, meaning "every minute," "every hour," etc. Forgetting this leads to jobs running far more often than intended.
- **Cron Trigger Directories:** Files placed in `/etc/rc0.d/` run during system shutdown/power-off — not during normal operation.
- **Single vs. Double Quotes:** Use single quotes for `sed` scripts to prevent the shell from interpreting special characters like `$` as shell variables. If double quotes are used, `$` must be escaped as `\$`.
- **`y` vs Ranges:** The `y` (transliterate) command does **not** support character ranges like `a-z`. Each character must be specified individually, unlike `tr`.
- **`wc` Emulation:** `sed -n '$=' file` prints only the total line count of a file, emulating `wc -l`.

## 🏆 Master Concept List — Top 25 Exam-Critical Terms

1. **`sed`** — Non-interactive, POSIX-compliant stream editor for efficient one-pass text transformation
2. **Pattern Space** — Primary volatile buffer where the current line is loaded for processing
3. **Hold Space** — Secondary persistent buffer for storing data across cycles
4. **`-n` flag** — Essential flag to suppress default automatic output of the pattern space
5. **`s///g`** — Global substitution command replacing all occurrences on a line
6. **Execution Cycle** — The Read → Execute → Display loop applied to every input line
7. **Addressing** — Selection of target lines via numbers, regex, ranges, or step expressions
8. **`-i` flag** — Modifies files directly through in-place editing
9. **Branching (`b`/`t`/`T`)** — Flow control mechanisms within a `sed` script
10. **`N` command** — Joins lines by appending the next line to the pattern space buffer
11. **Cron Tab** — System scheduling tool for periodic automated task execution
12. **`-E` flag** — Enables Extended Regular Expressions without backslash requirements
13. **Backreferences (`\1`, `\2`)** — Reusing captured groups from parentheses in replacement text
14. **`&` symbol** — Reference to the entire matched pattern in a substitution replacement
15. **`x` command** — Swapping contents between pattern space and hold space
16. **Address Range (`start,end`)** — Processes lines from a start match to an end match
17. **`!` (Negation)** — Reverses address matching, applying commands to non-matching lines
18. **`=` command** — Outputs the current line number for tracking and debugging
19. **`~` (Step Addressing)** — Selecting every Nth line from a starting point (e.g., `1~2`)
20. **`q` command** — Immediate script termination after the current line
21. **`c` command** — Complete replacement of the current line with specified text
22. **`\U` / `\L`** — Case conversion modifiers for uppercase/lowercase in substitutions
23. **Shebang (`#!/bin/sed -f`)** — Defining the interpreter for standalone `sed` script files
24. **`-f` flag** — Executing a `sed` script from an external file
25. **Cron Field Order** — Minute, Hour, Day of Month, Month, Day of Week (strict sequence)
