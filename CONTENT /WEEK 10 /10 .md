## Week 10 — Version Control, Hardware Discovery, and Prompt Strings
> 💡 **One-line summary:** Week 10 covers the mechanisms of software versioning (Git/SVN), hardware reliability through RAID, and system monitoring/customization using hardware discovery tools and shell prompt variables.

---

### 🔑 Core Concepts

#### Version Control
A system that tracks every save as a new version of code, allowing programmers to trace changes and revert to previous working states. A modular approach (separate functions in separate files) dramatically increases the number of versions to track, making version control a mandatory database tool for clarity.

> 📝 **Exam note:** Remember that modular programming is the *reason* version control becomes essential — more files and more versions per file demand systematic tracking.

---

#### SVN (Subversion)
A **centrally hosted** version control system where a master server manages the official code version. If the central server fails, it causes complete downtime — a critical single point of failure.

---

#### Git
A **distributed** version control system where every user has a complete project copy, providing high redundancy and allowing independent branching. Distributed copies allow users to work independently and start new "threads" or branches.

> 📝 **Exam note:** The key advantage of Git over SVN is that no single server failure can halt development — every clone is a full backup.

---

#### .git Directory
A hidden directory created during `git init` that contains **hooks**, **logs**, **objects**, and **references** necessary for tracking versions. It acts as the primary database for all local version tracking. Use `ls -la .git` to view its hidden contents.

---

#### Remote Server Types
Git repositories can be hosted on various remote servers including local Git servers, campus servers, GitLab, and GitHub.

---

#### GitHub Arctic Vault
An underground storage facility where GitHub stores copies of code to ensure data safety even during major catastrophic events such as data center attacks.

---

#### Personal Access Token (PAT)
A secure alternative to passwords used for authenticating Git actions (like pushing) to remote servers like GitHub. Standard GitHub passwords are no longer used for command-line Git actions; PATs are required for security. During configuration, users select specific scopes (e.g., "repo") to define the token's permissions.

> 📝 **Exam note:** A PAT is shown only once upon creation — copy and store it immediately (e.g., in `~/.by_p_a_t` using `vim`). If lost, you must delete and recreate it.

---

#### Two-Factor Authentication (2FA)
A security layer requiring a password plus a second verification method (like a phone or token) to prevent unauthorized access.

---

#### RAID (Redundant Array of Independent/Inexpensive Disks)
A storage technology that distributes data across multiple disks to provide **redundancy**, fault tolerance, and increased speed. Speed increases because each disk in an array can respond to different parts of a file simultaneously. Configuring RAID disks creates a single **logical volume** (partition) for the system. Common levels include RAID 0, 1, 5, and 6.

---

#### RAID 0
Focuses on maximizing storage capacity by combining disks; it does **not** provide redundancy. If one disk fails, **all data** in the array is lost.

> 📝 **Exam note:** RAID 0 = zero fault tolerance. This is a frequent MCQ trap — do not confuse it with other RAID levels that offer redundancy.

---

#### RAID 5
Utilizes **distributed parity** and striping to balance data integrity, speed, and storage efficiency. Parity (error-correction data) is spread across all disks in the array.

#### RAID 5 Usable Space Example
In a setup with 4×8 TB disks (32 TB total), RAID 5 provides approximately **~26 TB usable space**; the remainder is lost to redundancy overhead.

> 📝 **Exam note:** Usable space is always lower than the sum of disk capacities. Know the specific 32 TB → ~26 TB example for numerical questions.

---

#### RAID Controller
A PCI card that manages communication between the system and the disk array; its capacity determines the number of connectable disks.

---

#### RAID Recovery Mechanism
When a failed disk is replaced, the RAID controller identifies the missing parts and automatically writes **only** that specific data to the new disk to restore normal configuration.

---

#### Hot Spare
An inactive disk in a RAID setup that automatically replaces a failed disk to restore the configuration without manual intervention.

---

#### Hardware Failure Factors
Hardware failure is considered certain over time due to moving parts and heat generation — this is a core motivation for RAID redundancy.

---

#### /proc/ Directory
A virtual filesystem containing real-time system information, such as CPU details (`/proc/cpuinfo`) and partitions (`/proc/partitions`).

---

#### Battery Health Assessment
A battery is considered in "good as new" condition if `energy-full` (current maximum capacity) equals `energy-full-design` (original manufactured capacity). Comparing these two values reveals battery degradation.

---

#### PS1 (Primary Prompt String)
The default bash prompt (typically `\u@\h:\w\$`) displayed when the shell is ready for a command.

---

#### PS2 (Secondary Prompt String)
The prompt shown (default `>`) when a command requires multi-line input, such as an unclosed quote.

---

#### PS3
The prompt string used specifically within `select` loops (default `#?`).

---

#### PS4
The prompt string (default `+`) used for execution tracing when debugging with `set -x`.

---

#### Escape Sequences for Prompt Strings
Specialized codes used to customize the information displayed in prompt strings:

| Escape Sequence | Meaning |
|---|---|
| `\u` | Current logged-in **username** |
| `\h` | System **hostname** |
| `\w` | **Full path** of current working directory |
| `\W` | **Basename** (last folder) of current working directory |
| `\A` | Current time (24-hour) as **hh:mm** |
| `\t` | Current time (24-hour) as **hh:mm:ss** |
| `\T` | Current time (12-hour) as **hh:mm:ss** |
| `\@` | Current time (12-hour) with **a.m./p.m.** |
| `\d` | Date in "**weekday month day**" format |
| `\s` | Name of the current **shell** (e.g., bash) |
| `\#` | Current **command number** in the session |
| `\$` | Displays `#` if UID is 0 (root), otherwise `$` |
| `\\` | Displays a **literal backslash** character |

> 📝 **Exam note:** PS1 strings often contain complex sequences like `\[\033...\]` — these are not text display codes but are used for **color formatting and bolding**.

---

#### Python Prompt Strings
Defined in the `sys` module as `sys.ps1` (default `>>>`) and `sys.ps2`. They can be made dynamic by overriding the `__str__` method.

> 📝 **Exam note:** Python prompts are controlled differently from bash prompts — they use `sys.ps1`/`sys.ps2`, not environment variables.

---

#### Collaboration Loop
The logical workflow of multiple people making and approving changes to a shared document or codebase — a core use case for version control systems.

### ⌨️ Commands & Syntax

| Command | Syntax | What it does |
|---|---|---|
| `git init` | `git init` | Initializes a new Git repository and creates the `.git` directory |
| `git remote add` | `git remote add <name> <url>` | Connects the local repository to a specified remote server URL |
| `git config` | `git config --global user.name "name"` | Sets the global username for Git commits |
| `git config` | `git config --global user.email "email"` | Sets the global email address required for Git commit authentication |
| `git add` | `git add <file>` | Stages specific changes in preparation for a commit |
| `git commit` | `git commit -m "msg"` | Commits staged changes to the local repository with a descriptive message |
| `git push` | `git push` | Uploads local commits to the remote server; requires a PAT for authentication |
| `lsblk` | `lsblk [-o NAME,SIZE]` | Lists all block-type storage devices; `-o` flag filters output columns |
| `lspci` | `lspci` | Lists all devices connected via the Peripheral Component Interconnect (PCI) bus |
| `dmidecode` | `sudo dmidecode --type memory` | Provides detailed information about installed RAM (DIMM modules) |
| `upower` | `upower -e` | Enumerates all power-related devices, such as batteries and AC paths |
| `upower` | `upower -i <path>` | Displays detailed status, capacity, and health for a specific battery path |
| `hdparm` | `sudo hdparm -Tt /dev/sda` | Performs a storage benchmark test for cached and buffered disk reads |
| `iostat` | `iostat -dx /dev/sda` | Displays real-time extended I/O statistics for CPU and storage usage |
| `ifconfig` | `ifconfig` | Displays the current network interface configuration |
| `echo $PS1` | `echo $PS1` | Displays the current configuration of the primary prompt string |
| `source` | `source .bashrc` | Reloads the bash configuration file to reset prompts to their default values |
| `set -x` | `set -x` | Enables execution tracing, which uses the PS4 prompt to show commands as they run |
| `ls -la .git` | `ls -la .git` | Lists hidden files and metadata inside the local Git database |
| `vim` | `vim ~/.by_p_a_t` | A recommended practice to store Personal Access Tokens in a hidden file for easy retrieval |
| `hwinfo` | `hwinfo` | Displays general hardware information |
| `lshw` | `lshw` | Lists detailed hardware configuration |
| `hardinfo` | `hardinfo` | Launches a GUI application for viewing comprehensive system details |
| `clinfo` | `clinfo` | Specialized tool for extracting detailed GPU specifications |
| `cat` | `cat /proc/cpuinfo` | Views detailed CPU hardware specifications |
| `cat` | `cat /proc/partitions` | Views all detected disk partitions |

**Key flags reference:**

| Flag | Effect |
|---|---|
| `-o NAME,SIZE` | (`lsblk`) Filters output to show only device names and sizes |
| `--type memory` | (`dmidecode`) Limits output to RAM/DIMM module information |
| `-e` | (`upower`) Enumerates all power-related devices |
| `-i <path>` | (`upower`) Shows detailed info for a specific power device |
| `-Tt` | (`hdparm`) Runs cached (`-T`) and buffered (`-t`) read benchmarks |
| `-dx` | (`iostat`) Extended disk statistics with device utilization |
| `-m "msg"` | (`git commit`) Attaches a commit message inline |
| `--global` | (`git config`) Applies configuration to all repositories for the user |
| `-la` | (`ls`) Lists all files including hidden ones in long format |
| `-x` | (`set`) Enables execution tracing for debugging |

### ⚖️ Key Comparisons & Distinctions

| Centralized VCS (SVN) | Distributed VCS (Git) |
|---|---|
| Single master server holds all history | Every user has a full copy of the repository |
| Server failure = total downtime | No single point of failure; high redundancy |
| Legacy system, vulnerable to failure | Modern standard with branching and offline work |

| `\w` in Prompts | `\W` in Prompts |
|---|---|
| Displays the **full** current working directory path | Displays only the **basename** (last folder) |

| Password Authentication | PAT Authentication |
|---|---|
| *Deprecated* — no longer accepted for CLI Git operations | Required for all command-line Git actions on GitHub |
| Less secure | Scoped permissions, revocable, more secure |

| RAID 0 | RAID 5 |
|---|---|
| Zero fault tolerance | Tolerates one disk failure |
| Maximum storage capacity (full sum of disks) | Reduced usable space due to parity overhead |
| All data lost if any single disk fails | Data survives and rebuilds automatically |

| `energy-full` | `energy-full-design` |
|---|---|
| Current maximum capacity of the battery | Original manufactured capacity |
| Decreases over time with use | Fixed value from factory |
| If equal → battery is "as good as new" | Baseline for comparison |

| Bash Prompts (`PS1`–`PS4`) | Python Prompts (`sys.ps1`, `sys.ps2`) |
|---|---|
| Controlled via environment variables | Controlled via `sys` module attributes |
| Customized with escape sequences (`\u`, `\h`, etc.) | Customized by overriding the `__str__` method |

### ⚠️ Common Exam Traps

- **Super-User Requirements:** Hardware commands like `dmidecode`, `fdisk`, and `hdparm` often fail unless executed with `sudo`. Always check if `sudo` is needed.

- **RAID 0 Failure:** Unlike RAID 5 or 6, RAID 0 provides zero fault tolerance; if one disk fails, all data in the array is lost. Do not assume "RAID" always means "redundant."

- **RAID Usable vs. Actual Space:** Usable space is always lower than the sum of disk capacities because portions are reserved for redundancy/parity. Know the 4×8 TB → ~26 TB example.

- **Prompt Reset:** Changes made to `$PS1` directly in the terminal are temporary; they will revert upon logout unless saved in `.bashrc`.

- **PAT Security:** If a PAT is compromised, it must be **revoked** via GitHub developer settings to immediately restrict access.

- **PAT Persistence:** When creating a PAT on GitHub, it is hidden after the initial creation; users must copy and store it immediately or they will have to delete and recreate it.

- **Prompt Formatting Strings:** PS1 strings often contain complex sequences (e.g., `\[\033...\]`) which are not for text display but are used for **color formatting and bolding** — do not confuse these with escape sequences like `\u` or `\h`.

- **RAID Recovery is Partial:** When a failed disk is replaced, the RAID controller writes only the specific missing data to the new disk — it does not rewrite the entire array.

## 🏆 Master Concept List — Top 25 Exam-Critical Terms

1. **`Git`** — Distributed version control system where users hold full project copies for redundancy and independent branching
2. **`RAID`** — Technology combining multiple disks for redundancy, fault tolerance, and performance
3. **`PS1`** — Environment variable defining the primary shell prompt appearance and information
4. **`Redundancy`** — The practice of duplicating data (via RAID or Git) to prevent loss during hardware or server failure
5. **`Personal Access Token (PAT)`** — Security token required to authenticate Git `push` actions on GitHub
6. **`RAID 5`** — RAID level using striping and distributed parity for a balance of speed, storage, and fault tolerance
7. **`.git` folder** — The core hidden directory of a Git repository containing all version tracking data (hooks, logs, objects, references)
8. **Staging (`git add`)** — The intermediate step of selecting specific changes before committing them
9. **Committing (`git commit`)** — Saving staged changes to the local repository history with a descriptive message
10. **`lsblk`** — Command to view block storage devices and their mount points
11. **`dmidecode`** — Tool to extract hardware info (like RAM) from the system DMI table; requires `sudo`
12. **`hdparm`** — Utility to view/set hard disk parameters and test read speeds
13. **`upower`** — Service for managing and viewing power source/battery information
14. **`PS2`** — Secondary prompt displayed when a command is incomplete (e.g., open quotes)
15. **`PS4`** — Prompt prefix used during `set -x` execution tracing (default `+`)
16. **Escape Sequence `\u`** — Represents the current logged-in user in a prompt string
17. **Escape Sequence `\h`** — Represents the system hostname in a prompt string
18. **Escape Sequence `\w`** — Represents the full path of the current working directory
19. **Distributed Parity** — RAID 5 mechanism that spreads error-correction data across all disks
20. **`source .bashrc`** — Command to apply changes made to the bash configuration file immediately
21. **Hot Spare** — A standby disk ready to automatically replace a failed drive in a RAID array
22. **`lspci`** — Command used to list all peripheral component interconnect devices
23. **`SVN`** — Legacy centralized version control system vulnerable to single-point-of-failure
24. **`iostat`** — Tool for monitoring system input/output device loading and CPU usage
25. **GitHub Arctic Vault** — Underground storage facility for catastrophe-proof code preservation
